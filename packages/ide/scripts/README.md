# 场景平台部署脚本说明

## 业务背景

这是一套用于部署「场景低代码开发平台（SOLO）」的自动化脚本。每次部署的核心目标是：让前端平台能够加载并展示一个具体的场景（比如"LCTechPark 龙湖科技园区"），包括该场景的区域树结构、设备信息等。

一个场景的数据分散在三个地方：

- **MySQL 数据库**：存储场景的基础表结构和业务数据
- **后端服务**（端口 8080）：管理场景数据，为前端提供 API 接口
- **前端配置**（.config 文件）：告诉前端平台加载哪个场景、场景叫什么名字、区域树结构是什么

部署的本质就是把一个场景压缩包（.zip）里的数据正确地放入这三个位置，让它们互相匹配。

---

## 五个脚本分别做什么

### sp-install.sh — 环境初始化

这是整个流程的第一步，负责搭建运行环境。

它做的事情是：拉取最新的 Docker 镜像，销毁之前可能存在的旧容器，删除 MySQL 的数据卷（保证每次都是一个干净的数据库），然后通过 docker-compose 启动所有服务容器。最后会等待 MySQL 完全就绪。

**为什么需要这一步**：因为场景中有些数据是通过 SQL 文件导入数据库的，有些是通过后端 API 导入的，这两者都需要对应的服务已经在运行。

**注意**：这个脚本每次运行都会清空数据库，所以它适合全新部署或彻底重置的场景。

---

### sp-import.sh — 数据导入

环境就绪之后，这一步负责把场景数据导入到系统中。

它解压场景压缩包，从中找到 SQL 文件并导入到 MySQL 数据库，建立场景需要的基础表结构。然后把整个压缩包作为文件上传到后端 API 接口（`/scenes/import`），由后端解析并加载场景的详细数据。

**这一步完成后**：数据库里有了场景的表结构和数据，后端服务也加载了场景信息。但前端还不知道要加载哪个场景。

---

### sp-deploy.sh — 配置部署

这一步负责让前端平台知道应该加载哪个场景。

它解压场景压缩包，从中找到场景的 JSON 配置文件（通常是 scene.json），读取里面的场景 ID（sceneId）和场景编码（code）。然后把这个 JSON 文件重命名为 `{场景编码}.config` 格式，复制到前端项目的指定目录下。最后重启前端的 solo-ide 服务，让它加载新的配置文件。

**.config 文件的作用**：前端编译时会通过 Vite 自动发现目录下的 .config 文件，运行时解析里面的内容，确定要加载的场景 ID、场景名称、区域树结构等。没有这个文件，前端就不知道该展示哪个场景。

**这一步完成后**：前端可以正确加载并展示场景。

---

### sp-templates.sh — 自定义模板部署

这一步负责把场景压缩包里的 `templates.json` 转换成低代码平台运行时需要的模板文件。

它会筛选页面级模板和控件级模板：页面级模板写入 `farris-vue-form-templates`，控件级模板合并到 `farris-designer/assets/widget-templates.json`。

**这一步完成后**：表单向导能看到自定义页面模板，设计器模板面板能看到自定义控件片段。

---

### sp-initialize.sh — 场景初始化

这个脚本把场景初始化需要的步骤串联起来，按顺序自动执行。

它会导入数据、部署自定义模板，最后部署运行时场景配置。整个过程只需要提供场景压缩包路径，其他路径使用脚本里的固定默认值。

---

## 脚本之间的关系

这是一个有先后依赖关系的流水线：

**sp-install.sh** 最先执行，它创建了一个干净的运行环境。没有它，后面的脚本连数据库都连不上。

**sp-import.sh** 依赖 sp-install.sh 的输出——MySQL 和后端服务必须先启动，它才能导入数据。如果跳过这一步直接运行 sp-deploy.sh，前端虽然能加载配置文件，但通过 sceneId 去后端查询时会发现数据库里没有对应的场景数据。

**sp-templates.sh** 依赖压缩包中的 `templates.json`，它不依赖数据库，但需要在 sp-deploy.sh 重启前端之前执行，这样重启后模板文件也已经就绪。

**sp-deploy.sh** 在概念上可以独立运行（它不需要数据库），但实际使用时必须在 sp-import.sh 之后——因为只有数据已经导入，前端加载配置后查询到的 sceneId 才在数据库里有对应的记录。

简单来说：install 搭台子，import 放数据，templates 放模板，deploy 让前端看到数据。四个环节一起构成完整部署。

---

## 使用方式

### 一键部署（最常见）

```bash
./sp-initialize.sh <场景压缩包路径>
```

例如：

```bash
./sp-initialize.sh /root/LCTechPark.zip
```

如果不传参数，脚本会交互式提示输入。

### 分步执行

```bash
# 第一步：初始化环境
./sp-install.sh

# 第二步：导入数据
./sp-import.sh /root/LCTechPark.zip

# 第三步：部署自定义模板
./sp-templates.sh /root/LCTechPark.zip

# 第四步：部署配置
./sp-deploy.sh /root/LCTechPark.zip
```

### 常见场景

如果只是想更新场景配置（比如改了区域树结构，数据库不需要重新导入），只运行 sp-deploy.sh 就可以了。

如果需要按当前场景包重新初始化，运行 sp-initialize.sh 即可。

如果只是想重新导入数据（比如换了一个场景包），先运行 sp-install.sh 重置环境，再运行 sp-import.sh 导入新数据，最后运行 sp-deploy.sh 部署配置。

---

## 注意事项

- sp-install.sh 会删除 MySQL 数据卷，每次运行都会清空数据库，请谨慎操作
- 所有脚本运行在同一台服务器上
- 场景压缩包需要包含 SQL 文件（用于建表）和 JSON 文件（用于前端配置）
